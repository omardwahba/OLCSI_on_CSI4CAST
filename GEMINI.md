# CSI-4CAST Context Guide

## Project Overview
**CSI-4CAST** is a comprehensive framework for generating and evaluating Channel State Information (CSI) prediction models using 3GPP TR 38.901 channel models. It supports large-scale dataset generation, deep learning model training (using PyTorch Lightning), and extensive robustness/generalization testing.

### Key Components
*   **`src/data`**: **Data Generation Module**. Uses the [Sionna](https://github.com/NVlabs/sionna) library to simulate realistic channel responses (time-domain/frequency-domain) under various mobility and delay spread conditions.
*   **`src/cp`**: **Channel Prediction Module**. The core training framework.
    *   **Entry Point**: `src/cp/main.py`
    *   **Models**: Defined in `src/cp/models/` (Base class: `BaseCSIModel`).
    *   **Config**: Managed by `src/cp/config/config.py`.
*   **`src/noise`**: **Noise Module**. Handles realistic noise modeling (Phase noise, Burst noise, etc.) and calibration.
*   **`src/testing`**: **Evaluation Module**. Metrics (NMSE, SE), computational overhead profiling, and visualization tools.
*   **`scripts/`**: SLURM templates for HPC execution (Phoenix cluster).
*   **`z_artifacts/`**: Designated output directory for datasets, model checkpoints, logs, and visualization results.

## Building and Running

### 1. Environment Setup
The project uses `mamba` (or `conda`) for environment management.
```bash
mamba env create -f env.yml
mamba activate csi-4cast-env
```

### 2. Data Generation
Generate CSI datasets before training. The script `src/data/generator.py` handles this.
*   **Training Data**: `python3 -m src.data.generator --is_train`
*   **Test Data (Regular)**: `python3 -m src.data.generator`
*   **Test Data (Generalization)**: `python3 -m src.data.generator --is_gen`
*   **Debug Mode** (Minimal data): Add `--debug` flag.

*After generation, compute normalization statistics:*
```bash
python3 -m src.utils.norm_utils
```

### 3. Model Training
Training is driven by `src/cp/main.py` using configuration files generated by `src/cp/config/config.py`.

**Step A: Generate Config**
```bash
# Example
python3 -m src.cp.config.config --model rnn --output-dir z_artifacts/config/cp/rnn/ --is_U2D False --config-file yaml
```

**Step B: Train**
```bash
python3 -m src.cp.main --hparams_csi_pred z_artifacts/config/cp/rnn/tdd_rnn.yaml
```
*   **Outputs**: Checkpoints and TensorBoard logs in `z_artifacts/outputs/`.
*   **Monitoring**: `tensorboard --logdir z_artifacts/outputs/[path]/tb_logs`.

### 4. Testing & Evaluation
*   **Performance**: `python3 -m src.testing.prediction_performance.main --model [model_name]`
*   **Overhead**: `python3 -m src.testing.computational_overhead.main`
*   **Analysis**: `python3 -m src.testing.results.main` (Aggregates results)
*   **Visualization**: `python3 -m src.testing.vis.main` (Generates plots in `z_artifacts/outputs/testing/vis/`)

## Development Conventions

*   **Code Style**: The project uses `ruff` for linting and formatting.
    *   Configuration: `pyproject.toml`
    *   Run: `ruff check .` / `ruff format .`
*   **Module Invocation**: Always run scripts as modules from the root directory (e.g., `python3 -m src.module.script`).
*   **Path Management**: Use `src/utils/dirs.py` or relative paths carefully. Artifacts should strictly go into `z_artifacts/`.
*   **HPC Compatibility**: Scripts in `scripts/` are designed for SLURM. Ensure any new heavy processing tasks have corresponding SLURM templates if intended for cluster use.
